# Stage 7: Internal Pages

## Start when

The client has approved the homepage.

## Designer task

Design internal pages one at a time by composing the approved system and homepage patterns. Do not invent a new visual direction for each page.

## Cowork prompt

Use this prompt once per page:

```text
Help me design one internal page in Figma using the approved client system.

Page: [PAGE NAME]

Read first:
- the approved brief and page requirements
- the approved homepage
- the READY client DESIGN.md
- the approved Figma variables and components

Before changing Figma:
1. Confirm the page goal, audience task and priority action.
2. Inventory the available content and assets.
3. Propose the section order using approved homepage or system patterns.
4. Identify any genuinely new requirement and explain why the approved system cannot
   already handle it.
5. Show the plan and wait for Designer confirmation.

After confirmation, help me build desktop, tablet and mobile frames. Use only approved
variables and components. Do not introduce a new token, component or visual pattern
without asking first.

Test long content, missing content, extra list items, image crops and relevant interaction
states. Add responsive notes in Figma.

Finish with the DiscoverWeb design-standard audit. Report PASS or FAIL with exact Figma
locations and stop after this one page.

If the available Figma access cannot perform an approved action, give me the exact manual
Figma steps and wait while I complete them. Do not claim the action was completed.
```

## Finish each page when

- [ ] The page meets the approved brief
- [ ] The page uses approved system patterns
- [ ] Desktop, tablet and mobile frames are complete
- [ ] Long and missing content cases have been checked
- [ ] Responsive and interaction notes are present
- [ ] Audit failures are resolved
- [ ] The frame status is `Approved`

Repeat for each required page, then continue to `08_HANDOFF.md`.
