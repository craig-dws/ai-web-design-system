# Stage 6: Homepage

## Start when

The client design system is self-certified and `DESIGN.md` is marked `READY`.

## Designer task

Design the full homepage from the approved system. The homepage is a composition of approved variables and components, not a new visual direction.

## Cowork prompt

```text
Help me design the client homepage in Figma using the approved design system.

Read first:
- the approved client brief and sitemap
- the approved visual direction
- the READY client DESIGN.md
- reference/01_DESIGN_SYSTEM_RULES.md
- reference/02_DESIGN_QUALITY_STANDARD.md

Before changing Figma:
1. Confirm the homepage goal, primary audience task and priority action.
2. Inventory the supplied content and assets. Flag only gaps that materially affect design.
3. Propose the section order and map every section to approved variables and components.
4. Identify any genuinely new component or system decision and ask before adding it.
5. Show the proposed homepage plan and wait for Designer confirmation.

After confirmation, help me build the homepage in Figma:
- Use realistic approved content, not filler.
- Use only approved variables and components.
- Use Auto Layout and intentional resizing behaviour.
- Create desktop, tablet and mobile frames.
- Define hover, focus, active, disabled, error and loading states where relevant.
- Test long headings, long labels, missing images and additional content items.
- Add responsive and interaction notes directly in Figma.

Finish with a DiscoverWeb design-standard audit and a design critique. Report exact
failures and what must be fixed before client review. Do not describe an automated check
as accessibility certification or client approval.

If the available Figma access cannot perform an approved action, give me the exact manual
Figma steps and wait while I complete them. Do not claim the action was completed.
```

## Review and approval

The Designer fixes every mandatory issue and presents the homepage to the client. Record written client approval and requested refinements.

- [ ] Desktop, tablet and mobile are complete
- [ ] The homepage uses the approved system
- [ ] Required states and notes are present
- [ ] Content-resilience cases have been checked
- [ ] Audit failures are resolved
- [ ] Client approval is recorded
